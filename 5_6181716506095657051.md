---

## 2. Purpose of the Dataset

The dataset is designed for studying and predicting **customer churn in the telecommunications industry**.

The main machine-learning task is:

> Given information about a telecom customer's usage, billing, service history, demographics, equipment and interactions with the company, predict whether the customer is likely to leave the telecommunications provider.

This makes the dataset suitable for:

**Customer Churn Prediction → Customer Behaviour Analysis → Churn Factor Identification → Customer Retention Strategies**

## 4. Target Variable

The target variable is:

**`Churn`**

It contains two classes:

| Value | Meaning |
|---|---|
| `Yes` | Customer churned / left the company |
| `No` | Customer remained with the company |

For machine learning it can be converted to:

`Yes → 1`

`No → 0`

The original dataset documentation defines churn as churn occurring **31–60 days after the observation date**. Many usage-related "mean" variables summarize customer activity during approximately the four months before churn observation.

This is useful because the model is therefore attempting to use **past customer behaviour to predict future churn** rather than simply describing customers who have already left.

---

## 5. Class Distribution

The labeled dataset contains:

| Class | Customers | Percentage |
|---|---:|---:|
| Non-Churn | **36,336** | **71.18%** |
| Churn | **14,711** | **28.82%** |
| Total | **51,047** | **100%** |


Therefore, the dataset has a **moderate class imbalance**.

Approximately:

`71% → Stay`

`29% → Churn`

This is actually useful for our project because customer churn datasets in real businesses are often imbalanced.

For evaluation, we should therefore not depend only on accuracy. We should also use:

**Precision, Recall, F1-score, ROC-AUC and Confusion Matrix.**

---

## 15. Potential Data Quality Issues

Before ML training, we should check for:

**Missing values → incorrect data types → duplicated customers → unusual numerical values → outliers → inconsistent categorical labels → high-cardinality features → possible target leakage.**

Some variables have unusual values according to the original documentation. For example, `CurrentEquipmentDays` can include unexpected negative values, making validation and investigation necessary.

This gives us meaningful data-validation work for the AWS pipeline rather than working with an artificially perfect dataset.

---

## 16. Privacy and Ethical Considerations

The publicly released data is anonymized and does not expose obvious direct identifiers such as customer names, phone numbers or email addresses.

However, it contains demographic and socioeconomic attributes including:

**age, income category, credit information, occupation, household information and geographic/service-area information.**

These attributes could potentially introduce bias into a predictive model.

Therefore, the project should avoid interpreting correlations as proof that a demographic characteristic **causes** churn.

For an academic model we may analyze these variables, but a real production retention system should additionally evaluate fairness and the appropriateness of using sensitive customer characteristics.

---

## 17. Known Limitations

The major limitation is that this is an **older telecom dataset** originating from an earlier generation of the mobile telecommunications market.

Customer behaviour, pricing models, smartphones, internet usage and subscription structures have changed significantly since the data was collected.

Therefore:

> The dataset is suitable for demonstrating customer churn analytics and machine-learning techniques but should not be treated as representative of the modern 2026 telecommunications market without additional validation.

Another limitation is that the company identity and many operational details are anonymized, which limits some business interpretations.
