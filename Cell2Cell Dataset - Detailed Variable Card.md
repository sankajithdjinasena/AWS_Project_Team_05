# Cell2Cell Telecom Churn Dataset — Variable Card

## Important interpretation notes

The Cell2Cell documentation states that variables whose descriptions begin with **“Mean”** are averages calculated over the **four months before churn was observed**. `CHURN` records whether churn occurred roughly **31–60 days after the observation date**.

Although almost all columns are stored numerically, many are actually **categorical indicator variables** where:

- `1` = characteristic is present / true
- `0` = characteristic is absent / false

`CSA` is the main text/string variable. Published analysis classifies the expanded dataset as 36 continuous variables, 40 categorical variables, one text variable and one dependent churn variable.

# A. Customer Usage, Billing and Call Behaviour

| Variable | Full Meaning | Type | Detailed Explanation | ML / Analysis Treatment |
|---|---|---|---|---|
| **REVENUE** | Mean Monthly Revenue | Continuous | Average monthly revenue generated by the customer. It represents how much money the telecom provider receives from that customer on average. | Keep numeric. Useful for analysing whether high-value or low-value customers churn differently. |
| **MOU** | Mean Minutes of Use | Continuous | Average number of minutes the customer uses the mobile service. This is a broad measure of customer engagement with the network. | Keep numeric. Consider scaling for Logistic Regression. |
| **RECCHRGE** | Mean Total Recurring Charge | Continuous | Average recurring amount billed regularly to the customer for their service plan/subscription. | Numeric. Compare with `REVENUE` and `OVERAGE`. |
| **DIRECTAS** | Mean Director-Assisted Calls | Continuous/count average | Average number of directory-assistance calls made by the customer. | Numeric. Usually low-frequency and skewed. |
| **OVERAGE** | Mean Overage Minutes | Continuous | Average number of minutes used beyond the allowance included in the customer's plan. | Important billing/usage feature. High values may indicate plan mismatch. |
| **ROAM** | Mean Roaming Calls | Continuous/count average | Average number of calls made while roaming. | Numeric. Likely highly skewed because many customers may rarely roam. |
| **CHANGEM** | Percentage Change in Minutes of Use | Continuous | Measures how the customer's usage minutes changed compared with the preceding period. Positive values represent increased use; negative values represent decreased use. | Potentially important behavioural-change feature. Check extreme values/outliers. |
| **CHANGER** | Percentage Change in Revenue | Continuous | Measures change in revenue associated with the customer compared with the previous period. | Useful churn signal. Check large positive/negative outliers. |
| **DROPVCE** | Mean Dropped Voice Calls | Continuous/count average | Average number of voice calls that were unexpectedly disconnected or dropped. | Service-quality feature. Could indicate network dissatisfaction. |
| **BLCKVCE** | Mean Blocked Voice Calls | Continuous/count average | Average number of voice calls that could not be completed because they were blocked. | Service-quality feature. |
| **UNANSVCE** | Mean Unanswered Voice Calls | Continuous/count average | Average number of calls made/received without being answered. | Behavioural usage variable. |
| **CUSTCARE** | Mean Customer-Care Calls | Continuous/count average | Average number of calls the subscriber makes to customer service. | Potential dissatisfaction/service-contact indicator. |
| **THREEWAY** | Mean Three-Way Calls | Continuous/count average | Average use of the three-way calling service. | Numeric; likely sparse. |
| **MOUREC** | Mean Minutes of Received Voice Calls | Continuous | Average number of minutes associated with incoming/received voice calls. The original documentation describes this as “mean unrounded MOU received voice calls.” | Usage/engagement feature. |
| **OUTCALLS** | Mean Outbound Voice Calls | Continuous/count average | Average number of outgoing voice calls made by the customer. | Customer usage feature. |
| **INCALLS** | Mean Inbound Voice Calls | Continuous/count average | Average number of incoming voice calls received by the customer. | Customer usage feature. |
| **PEAKVCE** | Mean Peak Voice Calls | Continuous/count average | Average number of incoming and outgoing calls made during peak calling periods. | Usage-pattern variable. |
| **OPEAKVCE** | Mean Off-Peak Voice Calls | Continuous/count average | Average number of incoming and outgoing calls made during off-peak periods. | Compare against `PEAKVCE`. |
| **DROPBLK** | Mean Dropped or Blocked Calls | Continuous/count average | Combined measure representing the average number of calls that were either dropped or blocked. | Highly related to `DROPVCE` and `BLCKVCE`; check multicollinearity. |
| **CALLFWDV** | Mean Call-Forwarding Calls | Continuous/count average | Average number of calls using call-forwarding functionality. | Likely sparse. Consider distribution before modelling. |
| **CALLWAIT** | Mean Call-Waiting Calls | Continuous/count average | Average number of calls involving the call-waiting service. | Usage feature. |

The definitions above follow the Cell2Cell documentation, which reports these as four-month behavioural averages where “Mean” is specified.

|---|---|---|---|---|
| **CHILDREN** | Children Present in Household | Binary | Indicates whether children are present in the subscriber's household. | Categorical/binary. Consider fairness/privacy when interpreting. |
| **MARRYUN** | Marital Status Unknown | Binary | `1` indicates that the customer's marital status is unknown. | Treat as categorical indicator. |
| **MARRYYES** | Married | Binary | `1` indicates that the subscriber is recorded as married. | One-hot marital category. |
| **MARRYNO** | Not Married / Unmarried | Binary | `1` indicates that the subscriber is recorded as unmarried/not married. | One-hot marital category. |

The expanded Cell2Cell documentation explicitly identifies the three marital-status indicators as **unknown, married and unmarried/not married**. 

### Important

These three variables represent a single underlying concept:

```text
Marital Status
     │
     ├── MARRYUN  → Unknown
     ├── MARRYYES → Married
     └── MARRYNO  → Not married
```

For models sensitive to perfect multicollinearity, such as unregularized Logistic Regression, consider dropping one reference category.

# D. Credit-Rating Variables

These columns are essentially indicators representing different credit-rating categories. The published Cell2Cell dictionary defines the sequence from stronger to weaker ratings as follows.

| Variable | Meaning | Type | Explanation |
|---|---|---|---|
| **CREDITA** | Highest Credit Rating — A | Binary | Indicates membership in the highest A credit category. |
| **CREDITAA** | High Credit Rating — AA | Binary | Indicates membership in the AA/high credit category. |
| **CREDITB** | Good Credit Rating — B | Binary | Indicates a good/B credit rating. |
| **CREDITC** | Medium Credit Rating — C | Binary | Indicates a medium/C credit rating. |
| **CREDITDE** | Low Credit Rating — DE | Binary | Indicates a relatively low credit-rating category. |
| **CREDITGY** | Deficient / Very Low Credit Rating — GY | Binary | Indicates a poor/deficient GY credit-rating category. |
| **CREDITZ** | Lowest Credit Rating — Z | Binary | Indicates the lowest listed credit-rating category. |
| **CREDITAD** | Number of Credit-Rating Adjustments | Integer/count | Number of adjustments made to the customer's credit rating, either upward or downward. |

`CREDITAD` ranges beyond 0/1 in the expanded dataset, so it should be treated as a **count**, not a binary indicator. Published statistics report values as high as 25.

These variables may be sensitive socioeconomic attributes, so model interpretation should be handled carefully.

# K. Retention-Team Variables

| Variable | Full Meaning | Type | Detailed Explanation | Modelling Note |
|---|---|---|---|---|
| **RETCALLS** | Previous Retention Calls | Integer | Number of calls previously made to the company's customer-retention team. | Potentially powerful but check timing carefully. |
| **RETACCPT** | Retention Offers Accepted | Integer | Number of previous retention offers accepted by the customer. | May encode previous churn-risk intervention. |
| **RETCALL** | Has Called Retention Team | Binary | Indicates whether the customer has made a call to the retention team. | Audit carefully for temporal leakage. |

The source distinguishes `RETCALLS`, which is the **number of calls**, from `RETCALL`, which is simply whether such a call occurred.

These are valuable features but deserve a **data-leakage check**.

For example:

```text
If retention call happens BEFORE prediction date
        ↓
Valid predictor

If retention call happens AFTER customer already decided to leave
        ↓
Potential leakage
```

We need the exact temporal definition before automatically excluding them.

# N. Income Variables

| Variable | Full Meaning | Type | Detailed Explanation |
|---|---|---|---|
| **INCMISS** | Income Missing Flag | Binary | Indicates whether the subscriber's income information is missing. |
| **INCOME** | Income Category | Ordinal numeric | Recorded income group/category. The documentation specifies that `0` represents missing income data. |

The source reports `INCOME` values from **0 to 9**, meaning it should be treated as an income category/level rather than assuming that values represent literal currency amounts.

So:

```text
INCOME = 0
→ missing

INCOME = 1–9
→ recorded income category/level
```

Do **not** interpret:

```text
INCOME = 9
```

as `$9`, `$9,000`, etc. The available data dictionary does not provide that conversion.

# P. Churn Variables

There are actually two churn-related columns in the expanded data.

## CHURN

```text
CHURN
│
├── 1 → Customer churned
└── 0 → Customer did not churn
```

This is the primary outcome variable representing churn approximately 31–60 days after the observation date.

### Recommended use

```text
y = CHURN
```

## CHURNDEP

| Property | Description |
|---|---|
| **Variable** | `CHURNDEP` |
| **Meaning** | Churn dependent-variable copy used for the calibration/validation setup |
| **Values** | 0 / 1 where available |
| **Missing** | Missing for the validation sample |

The source explicitly describes it as:

> Churn, missing for the validation sample.


Published statistics show **31,047 missing values**, consistent with the validation portion of the dataset.

### Modelling decision

**Remove `CHURNDEP` from the predictor variables.**

Using it to predict `CHURN` would effectively expose target information.

```text

RECCHRGE
DIRECTAS

ROAM

```

for missing values and extreme values.

We should also check:

```text
AGE1 / AGE2
→ missing or suspicious zero ages

INCOME
→ 0 means missing

SETPRC
→ 0 means missing

CSA
→ categorical/text values

CUSTOMER
→ duplicates

CHURN
→ only 0/1

CHURNDEP
→ expected missing values
```

Published analysis of this version reports missing observations in 11 variables and notes outliers and multicollinearity in the raw data.
